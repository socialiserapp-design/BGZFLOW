# Contributing

Start from a reproducible user outcome or failure. Explain the intended behaviour,
scope and evidence; keep private transcripts, credentials and user-specific lessons
out of public issues and pull requests.

Read [AGENTS.md](AGENTS.md), the relevant source and affected method before editing.
Preserve the common working contract, original decisions and upstream licences.
Avoid extra mandatory planning, read receipts, reply blocks or duplicate trackers.

Run the checks affected by a change, including a useful regression for a reproduced
failure. Run the combined suite and both package builds for a release. Report
native host, outcome and recovery checks separately from unit tests. A selected
method or a green command alone does not prove the user's outcome.

Keep changes focused and describe limitations plainly. Add new routing behaviour
with relevant and unseen cases, including negative cases and partial/failure paths.
Performance claims need a clear baseline and comparable model, host, context and
workload. Do not turn a single successful example into a general superiority claim.

Update source/provenance records for imports and explain adaptations. New
permissions, spending or public external actions require the relevant authority.
