# Output and retrieval

First ask a narrower question: filenames, relevant symbols, changed lines, failed test names or selected fields. Process large results with local code before returning them to the model. Keep the original result addressable; retrieve surrounding context when interpretation depends on it.

Use existing RTK for supported shell commands when it preserves exit status and the information needed. Do not rewrite unknown commands, pipes or external actions merely to obtain a savings counter. Never repeat a mutation to recover output. A filtered success message does not verify a product outcome.

Use existing Headroom for suitable large structured results or repeated reads where originals can be retrieved. Do not apply it after RTK has already removed information from the same result. Do not compress exact user instructions, permissions, critical numbers or security evidence into an approximation. Retrieve originals before consequential conclusions.

Context Mode contributes a useful pattern: keep full output in a local searchable store and return relevant passages. Use an available implementation or existing file/search tools; do not add a second memory service just to follow this method. Native tool discovery and programmatic filtering often avoid a new service entirely.

For code or document indexes, verify workspace and freshness, retrieve source around matches and check dynamic boundaries. Graphify, CodeGraph and symbol indexes are alternatives, not a mandatory stack. Empty index results do not prove absence. Rebuild only affected indexes when possible; a short search is often cheaper.

Retain current decisions in native records; retrieve old chat material only on demand. Recovery should supplement native compaction, not replay the transcript or ask for a new chat. Missing context is retrieved when it matters to the task.
