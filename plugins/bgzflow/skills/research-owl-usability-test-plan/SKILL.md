# Usability Test Plan

Use this method only for the current research question. Reuse the existing brief, applicable user answers and private records; several selected methods contribute to one investigation, not repeated interviews. Inspect permitted actual evidence and preserve source links. Do not invent participants, quotations, emotions, findings, measurements or approvals; mark hypotheses and missing data explicitly. Planning a study does not authorise recruitment, messages, recording, tracking installation, spending, account changes or product changes. The current task and host permissions govern; shared automatic records are not proof that a study ran.

Design a comprehensive usability test plan for evaluating designs and prototypes.

## Instructions

1. **Define objectives**: What specific questions should this test answer?
2. **Create the test plan** with:
   - **Research questions**: the consequential questions this study must answer
   - **Methodology**: Moderated vs unmoderated, remote vs in-person, think-aloud protocol
   - **Participants**: Screening criteria, a sample appropriate to the question, segment diversity and intended inference; no universal five-user rule, recruitment approach
   - **Tasks**: necessary realistic task scenarios with success criteria and expected completion time
   - **Metrics**: Task success rate, time on task, error rate, SUS/SEQ scores, satisfaction rating
   - **Facilitation guide**: Script for introduction, task delivery, probing, and debrief
   - **Data collection**: What to record, observation template, note-taking framework
   - **Analysis plan**: How findings will be synthesized and prioritized
3. **Include a pilot test checklist**: What to verify before the real sessions.
4. Explain the relevant rationale and evidence. Present in a ready-to-use format.
