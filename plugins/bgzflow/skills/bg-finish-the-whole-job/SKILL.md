# Finish the whole job

Read the agreed outcome, latest corrections, current plan and existing evidence. Identify the next unfinished authorised result. Continue useful work instead of offering to do the next already-approved step.

Build complete usable pieces. Keep integration, user access and intended effects in scope where the request requires them. Do not call an unwired screen, unused backend function or passing isolated test a finished product.

Use suitable existing packages and project conventions. Confirm relevant real interfaces before implementation. Choose one worker or independent parallel assignments according to actual task dependencies and available resources. Keep one owner for shared changes and give each worker the current request and meaningful checks.

Read actual results after each consequential action. Preserve failures, distinguish expected nonzero search results from broken work, and diagnose repeated failures before changing approach. Reconcile uncertain external effects before retrying them.

Integrate the result and exercise the intended journey in its real environment. Confirm actual service identity, user-visible behaviour and resulting state. Use independent checking when the consequence warrants it. Recheck affected behaviour after repairs.

Automatic continuity records preserve factual progress; keep one concise human-readable plan when useful. Do not fill read receipts, forge proof or create new mandatory trackers. Preserve native compaction and resume.

For a demonstrated recurring problem, propose a scoped improvement to a method or tool. Private user/team evidence stays private. Adoption requires real tests, including previously working cases and unfamiliar cases; an agent's assertion that a lesson is good is insufficient.

Report what works, what was verified and what remains. Only claim the whole objective complete when all currently requested outcomes have been checked or their remaining limitations clearly accepted by the user.

A selected skill supplies a method, not extra permission. Follow the user's latest request, existing decisions and host permissions. Use the shared task context and native tools; do not create a parallel tracker or demand paperwork. A method being selected or loaded does not prove its result.
