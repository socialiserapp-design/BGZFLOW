# Shared BGZFLOW language

Keep the user's own product vocabulary and existing identifiers. These definitions
support clear communication; they do not require new files, forms or numeric gates.

## Roles

| Term | Meaning |
|---|---|
| User / founder | Owns product, design, business decisions and authority. |
| Lead / owner | Accountable for the requested outcome and coordination; may execute connected work directly. |
| Worker | Executes a bounded assignment within its permissions. |
| Independent checker | Assesses work it did not author; a separate provider alone does not establish independence. |
| Integration writer | The single owner combining changes to a shared candidate. |

## Work and evidence

| Term | Meaning |
|---|---|
| Outcome | The real result the user wants, beyond producing files. |
| Requirement | An observable behavior or constraint from the current request. |
| Decision | A choice with its actual author, scope and status; a superseded choice is history. |
| Assumption | An inference needing evidence or clarification, never permission. |
| Contract | Shared interface, identity, failure and compatibility expectations at a boundary. |
| Brief | The objective, inputs, limits, ownership, outputs and checks for an assignment; it cannot override higher-priority instructions. |
| Candidate | The actual source, artifact and configuration under evaluation. |
| Worker-complete | An assigned contribution is ready for the owner's assessment. |
| Integrated | A contribution is present in the combined candidate. |
| Evidence | Inspectable source or observed behavior tied to the actual candidate and environment. |
| Finding | A concrete defect or missing requirement, retained until resolved or explicitly accepted within authority. |
| Accepted | The accountable owner has sufficient evidence for the relevant scope. |
| Verified live | The actual deployed instance passed the relevant observed checks. |
| Release authority | Permission for a particular external action; tests and reviews cannot create it. |
| Uncertain effect | An external operation whose result is unknown and must be reconciled before retry. |
| Hold | A current instruction preventing specified actions until its condition or authority changes. |

A review may conclude that work is supported, requires changes or lacks evidence.
These conclusions describe observations; they do not require JSON verdicts or
grant permission. Evidence from a component never automatically proves the whole
product.

## Context and resources

| Term | Meaning |
|---|---|
| Checkpoint | A concise current view of objective, decisions, work, evidence, gaps and next action in existing context or records. |
| History | Preserved original evidence and superseded decisions, separate from current authority. |
| Handoff | Necessary context delivered to another executor or host; no fixed byte cap or forced new chat. |
| Native continuity | The host's own conversation and compaction, supported by restored relevant context where hooks exist. |
| Overlay | Private user/team preferences, decisions and permitted resources, separate from shared package defaults. |
| Capacity | Actually available account/tool/device resources; several models may share one allowance. |
| Job / session | Native host identities used to correlate execution and recovery; a name or title alone is not proof. |

## Methods

| Term | Meaning |
|---|---|
| Skill catalogue | Available method metadata; discovering a skill does not load or apply it. |
| Selection | Choosing relevant methods and arrangements for the current task using Jev or the main-agent fallback. |
| Delivery | Supplying selected instructions to the actual executor. |
| Application | Observable use of an appropriate method in the work. |
| Coverage | The expertise and checks needed by this task's actual risks, not a fixed universal checklist. |
| Improvement | A tested change that helps relevant outcomes without unacceptable regressions; not simply a larger library. |

"Test everything" means the applicable agreed requirements and meaningful failure
cases, not all imaginable inputs. "Use all the skills" means consider the available
library and load useful compatible methods, not paste every skill into every prompt.
