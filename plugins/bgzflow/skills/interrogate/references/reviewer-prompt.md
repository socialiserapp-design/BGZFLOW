# Optional independent review brief

Supply only relevant sections: the original user outcome and latest corrections; exact candidate; affected callers and interfaces; known constraints; actual evidence and missing checks; read-only access and requested review scope.

Ask the reviewer to inspect source and observations independently. The builder's explanation is a hypothesis, not the specification. Identify a mismatch between the stated plan and the user's request when it changes the outcome.

For a finding, return its reachable trigger, location, consequence, direct evidence or reproduction, and a proportionate correction. Label unresolved concerns separately from demonstrated defects. Do not invent a bug quota, confidence gate, second provider or fixed output template.

For each material issue, use [the shared impact ratings](impact-ratings.md): harm
1–10 and how often 1–10 separately, with an unknown rating where evidence is missing.
State confirmed/probable/unverified evidence, occurrence scope and observation
basis, affected people/data/money, recovery, urgency and next action. Do not rank
by reviewer agreement or average away a rare catastrophic consequence.

The reviewer does not edit, deploy, disclose data or change accounts unless separately authorised. A completed review is an observation to assess, not permission or proof of the whole product. No findings is a valid result; state material coverage limits.
