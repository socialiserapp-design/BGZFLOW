# Jev for context and records

Use the [shared Jev method](../bg-jev/references/methods.md), levels seven through
nine, and the foundation's existing continuity store. Native event capture owns
recording. This method helps retrieve and interpret; it does not create another
memory database, manual read receipt or gate before replying.

Rank relevant excerpts against the latest request. Preserve original user decisions,
who said them, scope, source date and supersession relationships. An agent proposal
is not a user decision. Conflicting or uncertain evidence remains visible; a high
relevance score cannot make an old decision current or erase an inconvenient result.
Read decisive originals and check their freshness before acting.

A proposed memory update can be checked for duplication, contradiction, scope and
evidence support in one batch. Use the existing owner-approved write path. Relevance
filtering must never silently discard a new user correction or an unsettled question.
Preserve original evidence automatically where supported and keep private lessons
within their user/team. This is retrieval assistance, not enforcement of all writes.

For compaction, use actual host context signals and native compaction in the same
conversation. Restore current objective, corrections, permissions, unresolved
questions, ongoing operations and evidence references. Never use a transcript-size
threshold to demand a new chat, and never interpret compression as permission to
forget a constraint. If native compaction information is unavailable, say so only
when relevant; continue ordinary work without a compulsory Jev preflight.
