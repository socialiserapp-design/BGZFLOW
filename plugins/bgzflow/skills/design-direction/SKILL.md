# Give the work an appropriate visual direction

Recover the audience, real content, intended action and approved references from
the shared brief. Decide what this surface primarily helps people do: operate a
tool, read information, make a considered choice or explore an experience. These
can overlap. A familiar task interface and an expressive campaign need different
criteria; novelty, restraint and a particular colour scheme are not universal goals.

For a settled identity, inspect a representative actual screen and the tokens or
components that implement it. Improve the requested area within that language.
For an unresolved identity, use the subject's real imagery, vocabulary and context
to develop meaningfully different candidates. Honour the requested amount of
exploration; otherwise show enough to resolve the choice. Explain what each option
helps, its readability/performance/content trade-off and what would be costly to
change. Do not invent previous client rejection or a preference for novelty.

Build a representative composition with realistic content before extending a new
direction across the product. Establish reading order, emphasis, spacing, type
roles, colour roles and imagery. Existing system fonts, multiple accents, pure
black/white, cards or shared branding can be correct when the brief supports them.
Check font and image rights; treat generated or placeholder content as such.

For responsive web work, adapt the composition to actual content and available
space. Test long headings, narrow containers, zoom and supported languages rather
than relying on one breakpoint or making every page phone-first. Distinguish prose
measure from dense data layouts. Preserve semantic reading order when rearranging
visual columns. Use existing components and layout primitives before custom ones.

Inspect the rendered result, not only source code or a prompt describing it.
Compare against the approved reference using the same viewport and content where
possible; record consequential differences in the existing project record. Pair
with accessibility or motion only when that part of the experience needs it.
A screenshot can show composition; it cannot prove the interaction or saved result.
