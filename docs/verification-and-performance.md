# Verification and performance

This report describes observations available on 6 November 2026. Component tests,
host observations, routing decisions and completed user outcomes are different
forms of evidence. None establishes universal reliability.

## Regression checks

The public 2.7.3 source ran the combined offline suite once: 324 checks, with 323
passing and one outdated late-outage fixture failing. The original failure was
retained. The fixture was made synthetic and repaired to exercise the intended
late failure rather than an earlier request-size boundary. The affected final
subset, including the complete foundation-hook file, then passed all 83 checks.

The new regressions cover oversized nominees in both input orders, changed
sources, entirely unassessable nominations, checked-primary retention after a
late outage, unchanged partial-result restoration, explicit-authority boundaries
and fixed-category diagnostics that exclude arbitrary exception text.

The earlier 2.7.2 release also completed a full 311-check local run. These counts
overlap; they must not be added together or described as independent trials.
Native checks below do not imply every bundled skill has been executed.

## Observed host outcomes

On Claude Desktop Code, ordinary requests naming no skills demonstrated:

- Actual local sound-helper use: valid stereo PCM, an exact three-second stem,
  energy near the supplied contacts, quiet gaps and byte-identical stem replay.
  The source input was preserved. Nobody auditioned the result.
- Actual SVG assembly: source geometry, order, repeated-frame hold, local
  references and separate one-shot/loop/reduced-motion rules passed structural
  checks. Browser playback was not observed.
- A repair without a formal plan: the agent inspected the supplied SDK, ignored
  stale notes, reused the SDK and inspected the saved export. An independent
  probe with unseen rows and an instrumented SDK passed.
- A contained offline payment repair: hidden checks covered original/repeated
  identities, conflicting details, independent purchases, failure-before-save
  and invalid amounts. No real payment provider was contacted. Concurrent
  independent processes were outside that test's demonstrated coverage.
- A genuine same-chat pause and correction: the file remained unchanged while
  paused; the later wording replaced the earlier wording while layout, font
  and colour stayed unchanged. This was not an in-flight crash or compaction test.

These host observations used the 2.7.2 integration before the public 2.7.3 routing
repair. The 2.7.3 change has separate regression and routing evidence; it must not
be described as having repeated every native journey in every host.

## Routing measurements

One installed 2.7.2 Codex arithmetic run answered correctly with no tools or file
changes and **zero Jev routing calls**. The worker took approximately **15.1
seconds**, including host/model startup. Reported usage was 31,372 input tokens
and five output tokens. That input includes the host's instructions and tool
catalogue; this run does not isolate BGZFLOW's token contribution. The Claude
Desktop arithmetic check also recorded zero routing calls.

Six recorded routing attempts in one large existing development conversation
fell back before verification. Offline reproduction established a defect where
one oversized nominated procedure could discard fitting recommendations. The
records did not retain all original nominee identities, so this is a reproduced
matching mechanism, not proof of the exact cause of every recorded failure.

The 2.7.3 repair compares fitting procedures, preserves its verified primary when
a later supporting scan stops, and marks remaining nominees unassessed. Partial
recommendations never mean the whole comparison completed or the task succeeded.

A small real-Jev snapshot used a library of 868 methods, including externally
installed methods beyond BGZFLOW's curated bundle:

| Ordinary request | Routing result | Measured routing time | Jev calls |
| --- | --- | ---: | ---: |
| Local interface sounds and a timed stem | Completed comparison; sound and verification methods recommended | 7.19 s | 32 |
| Contained offline retry repair | Completed comparison; test-driven method recommended | 5.04 s | 25 |
| Prepare a workflow plugin for GitHub publication | Partial; one primary retained and 56 nominees unassessed | 11.38 s | 50 |

For comparison, the prior version replayed the exact same recorded decisions,
without additional provider calls. It retained the first two completed choices
but discarded every recommendation in the publication case. Replay elapsed time
is not an end-to-end speed baseline.

The publication case also illustrates a domain-selection limitation: its primary
was a store-submission method, which does not by itself establish fit for GitHub
publication. That case is **not counted as correct overall selection**. The main
agent must assess actual scope and prerequisites before applying any method.
Algorithm completion and semantic correctness are separate measurements.

## What remains unproven

There is no controlled evidence here of general speed, cost or quality superiority
over the same agent without BGZFLOW, manual selection or another workflow plugin.
The three routing examples are not a benchmark across all tasks. Large libraries
can still consume many calls, select overlapping or wrong-domain methods, or hit
time/context limits. The main-agent fallback is an essential part of the design.

Further evaluation should use matched on/off runs, repeated and unseen tasks,
clear outcome graders, failed-selection and partial-selection rates, unnecessary
work, clarification quality, token usage, provider cost and time to a verified
result. Record the host, model, context and library versions for fair comparisons.

Longer real-project use, native crash/compaction/cross-provider recovery, complete
worker-consumption enforcement, real-device rendering and listening remain
separate work. Closed host capabilities cannot be supplied by a skill's wording.

## 2.7.5 history and comparison repair

The final affected offline run passed 78 checks. Both package builds passed;
four installed copies match their validated artifacts. Native Codex read-back
confirms twelve BGZFLOW hooks trusted and enabled, with five unrelated hooks
unchanged. The full 332-check suite above belongs to 2.7.4 and was not rerun for
this narrower repair.

Historical context delivery now tracks individual immutable sources per native
context generation. Changing an unrelated tool result or resuming an existing
session does not replay unchanged historical messages. New corrections remain
eligible, and actual compact/clear boundaries restore sources. Items that do not
fit are not marked as delivered; emitted partial excerpts or deferred pointers
retain the original source reference. Antigravity's explicitly ephemeral context
still needs invocation-scoped restoration. These are prepared-context records,
not proof that a model read the context or that its answer is correct. Existing
duplicate text already retained by a host conversation is not retroactively
removed.

Independent whole-procedure comparison packets now overlap within the existing
bounded concurrency. If a later winner comparison exceeds the local packet
budget, a genuinely fit-checked lead remains available with an honest partial
result; unassessed nominees do not become selected or acquire user authority.
This does not guarantee that every library entry fits a remote comparison.

An actual Claude command-line hook invocation reached Jev and prepared the full
9,868-character diagnosis method in 2.7 seconds. Its route remained partial for
an oversized additional nominee. The separate command-line OAuth session then
expired before a model or Read-tool turn, so this is hook/provider evidence,
not a completed Desktop journey. Desktop-specific verification remains separate.
