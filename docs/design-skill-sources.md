# Design methods: sources and integration

The later [substantive toolkit expansion](design-expansion.md) adds actual
compiler/probe code, component specifications, animation/prototype recipes and
Google extraction guides beyond the seven general specialists documented here.

The master `bg-personal-product-design` now coordinates seven selective methods.
They are BGZFLOW adaptations, not unmodified upstream installations or a promise
that seven reviews run for every task. Existing decisions, records, permissions
and outcome checks remain shared. The ordinary selector discovers their metadata;
no new hook, model call requirement or background service is introduced.

## Deliberate adaptations

Preserve useful craft, not conflicting authority. Removed compulsory brand
novelty, one-accent/palette/font bans, fixed direction/interview counts, forced
phone-first layouts, all-platform checks, mandatory memory/design files and
extra approval rituals. Existing explicit user choices still govern variety,
shared identity and supported surfaces. Vercel's fixed virtualization count and
blanket confirmation advice do not become new product rules. GOV.UK's visual
style or particular validation timing is not imposed on unrelated products.

Performance targets depend on the actual experience and supported devices.
Transforms/opacity are useful starting points, not a ban on measured effects.
WCAG 2.2 AA target-size minimum is 24 by 24 CSS pixels with its stated exceptions;
larger targets can be appropriate. The Design Tokens report is a Community Group
specification, not a W3C Standard. A clean scan or a model's score is not proof of
accessibility, usable design or a completed product.
