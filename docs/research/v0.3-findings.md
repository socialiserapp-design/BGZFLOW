# v0.3 research findings — 1 October 2026

We compared BGZFLOW's v0.2 finish line with current primary guidance. We adopted only changes that remove human actions, duplicated runs or avoidable waiting.

| Stage | Primary source and current practice | BGZFLOW comparison | Decision |
|---|---|---|---|
| Idea | [GitHub issue forms](https://docs.github.com/en/communities/using-templates-to-encourage-useful-issues-and-pull-requests/syntax-for-issue-forms) structure only information needed to start. | BGZFLOW already recovers short prompts, but could over-question. | **Adopt:** one outcome/constraints/acceptance contract; ask only a material product decision. |
| Design | [W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/) provides testable accessibility criteria. | The design skill includes accessibility and an early prototype. | **Keep:** clickable skeleton plus approved design contract; reject recurring taste reviews. |
| Build | [GitHub Actions concurrency](https://docs.github.com/en/actions/using-jobs/using-concurrency) supports one active job per concurrency group and cancellation of obsolete work. | `bg-heavy` serialized local work but provider slots were implicit. | **Adopt:** explicit account-plan build slots and one heavy local run; superseded safe CI work may cancel, external mutations may not. |
| Web test | [Playwright best practices](https://playwright.dev/docs/best-practices) recommends user-visible behavior, test isolation and resilient locators; its trace viewer retains failure evidence. | Whole-candidate journeys existed but runner details were open. | **Adopt:** Playwright before mobile cloud runs; agents consume failure artifacts, not live browser taps. |
| Mobile test | [Expo EAS Workflows E2E examples](https://docs.expo.dev/eas/workflows/examples/e2e-tests/) support Maestro jobs, while [Maestro's EAS guide](https://docs.maestro.dev/cloud/ci-integration/eas-workflows) keeps flows in CI. | v0.2 required real rehearsal but humans/agents could drive emulators interactively. | **Adopt:** Maestro on every mobile candidate; occasional BrowserStack real-device sampling; founder phone is design-only. |
| Release | [Apple phased release](https://developer.apple.com/help/app-store-connect/update-your-app/release-a-version-update-in-phases/) and [Google staged rollouts](https://support.google.com/googleplay/android-developer/answer/6346149) reduce blast radius. | BGZFLOW already says launch small and watch. | **Keep and clarify:** staged release is default when the store supports it; no new approval loop. |
| Store submission | [App Store Connect API](https://developer.apple.com/documentation/appstoreconnectapi) and [Google Play Developer API](https://developers.google.com/android-publisher) automate repeatable submission work. | Submission was a manual-capable runbook. | **Adopt where configured:** generate metadata and submit through official APIs, but payment, declarations and first-time legal answers remain human-authorized. |
| Monitoring | [OpenTelemetry semantic conventions](https://opentelemetry.io/docs/specs/semconv/) standardize correlated telemetry. | BGZFLOW watches live errors for one hour but did not require a vendor. | **Adopt vendor-neutral correlation IDs and release markers; reject** adding a mandatory monitoring service. |
| Recovery | [Kubernetes rollback guidance](https://kubernetes.io/docs/concepts/workloads/controllers/deployment/#rolling-back-a-deployment) illustrates revision-bound rollback. | Exact-candidate rollback rehearsal already exists. | **Keep:** one scripted rollback tied to the immutable candidate; reject generic “backup exists” claims. |
| Multi-agent orchestration | [OpenAI Agents SDK tracing](https://openai.github.io/openai-agents-python/tracing/) records spans and handoffs; [Anthropic's multi-agent research](https://www.anthropic.com/engineering/multi-agent-research-system) emphasizes delegation and parallel independent work. | BGZFLOW had durable job records but workers exited to ask questions and account attribution was weak. | **Adopt:** provider-neutral mailbox, job/account receipts and bounded concurrency. Reject a mandatory framework or forwarding agent. |

## Net simplification

The ladder replaces repeated manual emulator sessions, not adds another gate. Mail defaults prevent job restarts. Provider slots prevent doomed queueing. Account receipts replace inference from configured routes. The release retains one full suite, one real-platform rehearsal, one rollback and one independent review owned by the local lead.
