01 / THE OPERATING LOOP

Begin with the result people need.

Understand

Find the consequential unknowns.

Recover decisions, investigate facts and ask about choices that change the product. Discover omitted needs without making the owner name them.

Coordinate

Keep one accountable lead.

Select relevant skills. Give workers complete outcomes and clear ownership. Integrate ready work through the project's authorised delivery route.

Verify

Observe what actually happened.

Check the running candidate, the real journey and its effects. Preserve failures. Separate built, delivered and used successfully.

Build a complete journey.

Clarify the outcome → compare approaches → set a quality standard → build and integrate → exercise the real result → repair required failures → deliver within authority.

Expo testing is a separate optional capability. It can supply mobile journey evidence when the workflow, account and spending authority are configured. An audit does not require Expo, and Expo does not require an audit.

02 / QUALITY BEYOND GREEN TESTS

Know what “good” means. Then check it.

Find the benchmark.

Research current professional guidance, comparable experiences and maintained implementations. Challenge the premise and compare credible alternatives on the user's actual needs.

UI references can inform craft. Architecture examples can reveal better discovery, caching or recovery. Neither popularity nor a screenshot proves suitability.

Test the actual result.

Use exact assertions for facts and contracts; calibrated independent judgment for meaning, usefulness and craft. Inspect the content, first user experience and customer-visible promises.

A high average cannot cancel an essential failure. Missing evidence remains unverified. New product preferences belong to the owner.

Confirmed failures of required outcomes return to the existing builder and repair loop. Better ideas are recommendations until authorised. There is no universal quality score, fixed judge or promise of perfection.

03 / HONEST ENFORCEMENT

Judgment, code and the host each have a job.

Methods

Reason and challenge

Skills guide clarification, research, design, building and review. Loading a method does not prove that an agent applied it correctly.

Deterministic code

Record and validate

Hooks preserve source-linked events. Configured outcome checks validate the candidate, observations and required quality criteria. They do not make an unreliable judge truthful.

Host integration

Act and observe

The host supplies permissions, actual capacity, completion delivery, release tools and real browser/device/service access. Unconnected steps remain explicit gaps.

Full-access agents can bypass editable local checks. Strong release enforcement needs a protected host or CI path. BGZFLOW does not add a universal stop/reply gate.

04 / THE METHOD LIBRARY

Broad expertise. Selective context.

Find a method by task or topic. The main agent selects locally; authorised Jev assistance is optional.

103 skills

4x4

Explore a substantial idea, risky change or important decision through product, approach, practical delivery and failure questions. Use for /4x4 or a request for thorough questioning. Adapt to the answers, with no sixteen-question ceiling.

add-voice

Add Grok realtime voice when that provider is requested or selected through an authorised comparison. Wire speech-to-speech, safe authentication and the app microphone while preserving the product's approved interface and capabilities.

advisor

Obtain a bounded independent second opinion when the user explicitly asks for an advisor or another model's view. Use the requested model when available; otherwise explain the capability gap. Never enable recurring consultation automatically.

architect

Design interfaces and responsibilities for a substantial software change, compare meaningful alternatives and preserve existing constraints.

autopsy

Investigate a repeated or serious failure by reproducing it, comparing evidence and isolating its cause before choosing a repair.

bg-build-with-me

Coordinate a substantial requested outcome from understanding through real verification, choosing relevant skills and one or several agents as the work requires.

bg-check-it-before-release

Independently check a substantial completed result against the original request and real operating environment before an authorised release or completion claim.

bg-continue-my-project

Resume requested work after compaction, interruption, model changes or an uncertain operation while preserving decisions and avoiding duplicate effects.

bg-efficiency

Choose methods to reduce repeated context, tool output, failed loops and unnecessary work.

bg-egm-coarchitect

Use Google’s Elephant and Goldfish method when a substantial design benefits from deep-context planning and a genuinely fresh independent critique.

bg-expo-testing

Plan, set up and run Expo end-to-end testing using official Expo workflows/simulators and available agent-device, Argent or Maestro methods. Connect whole-product requirements to real app and service evidence; reconcile runs, failures and cleanup.

bg-finish-the-whole-job

Execute and integrate an agreed outcome through repair and meaningful verification, preserving scope instead of stopping at a partial implementation.

bg-full-spectrum-audit

Challenge and audit a whole software product, feature, codebase or change: discover unmet needs and missing capabilities, question the product concept, compare better ideas and approaches, and verify the experience and technical system end to end. Use for ultimate/comprehensive reviews, product critique, completeness and better-way questions, as well as code quality.

bg-jev

Use any relevant Jev capability for the current goal: typed judgments, scoring, research, evidence checks, context, risk, routing or composed workflows. Invoke as the general Jev entry point; select only the methods the task needs. Also diagnose BGZFLOW's existing skill/model selector.

bg-outcome-evals

Design and run checks that prove the user's intended outcome, including ongoing clarification, real browser/device/service effects, AI workflow evaluations, regression tests and deliberately broken cases. Use when defining completion, testing an agent or skill, or investigating a misleading green test result.

bg-personal-product-design

Coordinate product and visual design, relevant user research and asset reuse. Select focused design methods, the reference graph, sound/SVG tools or the Taste library for the actual task; preserve approved identity and verify the affected experience.

bg-plain-english-builder

Develop a shared understanding of a substantial request through thorough adaptive questioning, evidence and fair trade-offs before consequential choices. Continue clarification as the work evolves; more than sixteen questions can be useful when material unknowns remain.

bg-ship-and-recover

Deploy a verified candidate within existing authority, confirm the live result and recover safely from failures without duplicating external effects.

bg-zero-defect-gate

Compatibility entry for the former zero-defect review: use the full-spectrum audit and existing release verification without introducing another gate.

control-cli

Build or adapt a local harness to drive, inspect, and profile an interactive CLI or TUI without external services. Use for CLI UX checks, startup regressions, memory leaks, hangs, prompt flows, or terminal demos.

control-ui

Build or adapt a local browser/CDP harness to drive and inspect a web, IDE, or Electron UI. Use for local UI verification, screenshots, accessibility snapshots, perf profiles, visual diffs, or reproducing UI bugs.

create-loop

Create or adapt a recurring automation when the user requests a schedule or ongoing watch, using supported host scheduling and real result checks.

create-verification-skill

Generate a project-local verification skill that drives your app the way a user does — any language, framework, or platform. Use for /create-verification-skill, "make a control skill for this repo", or when a project has no scripted way to prove UI/CLI/service behavior.

design-accessibility

Find and repair accessibility barriers in the affected web or native journey: semantics, keyboard and focus, screen readers, contrast, zoom, target size and non-pointer alternatives. Use criterion-specific evidence rather than a blanket compliance claim.

design-animation-review

Inspect and improve actual animation timing, gesture handoff, interruption, choreography and frame performance using Emil Kowalski's detailed standards and implementation recipes. Use for motion review, janky interactions, drawers, toasts, transitions or coordinated animation; preserve approved effects.

design-component-library

Use detailed component anatomy, variant, state and accessibility specifications for advanced forms, navigation, overlays, calendars, trees, carousels and charts, with optional real-browser focus and RTL probes.

design-content

Write and test clear interface labels, instructions, forms, errors, empty states, progress and recovery messages. Use for terminology or localization problems; make wording match the actual product behaviour and preserve approved tone.

design-direction

Develop or refine visual direction, typography, composition and responsive web presentation for the actual audience. Use for visual concepts, landing pages, focused visual critique or approved-look polish; preserve a settled identity.

design-engineering-graph

Navigate a detailed cross-topic design-engineering reference graph when a task needs connected research across interaction, motion, typography, colour, layout, components, sound, SVG, diagrams or launch-film craft. Use for reference discovery and linked technical investigation; direct sound, SVG, motion and prototype tasks keep their specialist owners.

design-motion

Design and verify purposeful animation, gestures, transitions, 3D and visual effects on the intended platform. Use for motion quality, interruption, reduced-motion alternatives or measured rendering performance; preserve approved interaction and style.

design-native

Adapt an approved experience to its actual iOS, Android, desktop or resizable-window platform. Use for native navigation, input, safe areas, scalable text and adaptive layouts; select the installed stack-specific skill rather than forcing a migration.

design-product-flows

Improve task journeys, navigation, information hierarchy, dashboards, onboarding and form recovery. Use when people cannot find, understand or complete an action; distinguish observed usability problems from hypotheses.

design-prototype-lab

Build meaningful interactive design alternatives behind a live accessible variant picker, using Emil Kowalski's prototype procedure and concrete harness implementation. Use when a visual or interaction choice needs comparison before integrating the chosen direction.

design-sound

Design and generate requested interface sound families or motion-synchronised audio stems with local WAV synthesis, cue-sheet timing and Web Audio playback guidance. Use for UI sound, ticks/taps/chimes, Foley, sound palettes or audio matched to animation; preserve approved sound policy and real state.

design-stitch

Extract an existing frontend's design system locally using Google's detailed Stitch source-analysis guides, or use already-configured Stitch MCP tools for requested generation/editing and design-system transfer. Distinguish local no-account methods from optional remote operations and preserve approved design.

design-svg

Create or refine SVG artwork and assemble trusted local SVG frames into a self-contained animated flipbook with reduced-motion fallback, frame timing and optional inline colour variables. Use for icons, mascots, logo reveals, vector animation or existing vector-frame sequences.

design-system

Create or maintain reusable design tokens and components, coherent themes and design-to-code handoffs. Use for repeated UI drift or shared component changes; preserve the project's existing system and platform semantics.

design-taste-assets

Find and adapt real bundled Taste visual assets: shader effects, interactive components, SVG icons, diagrams, UI fragments, scenes, 3D/photo objects, photographs and layout examples. Use for actual asset/effect implementation or reuse, not ordinary copy changes, backend work or every design task.

design-token-build

Compile an existing compatible DTCG token source into concrete CSS variables, including aliases, composite values and source-defined dark overrides; inspect the output before integrating it.

design-web-colour

Build or debug perceptual web colour scales, OKLCH gamut, theme mappings and contrast using detailed CSS recipes. Preserve approved colours and existing token architecture.

design-web-typography

Implement or debug web type scales, font loading, metric fallbacks, OpenType numerals and variable fonts using detailed CSS recipes. Preserve approved typography and supported languages.

deslop

Remove AI-generated code slop and clean up code style

diagnosing-bugs

Diagnosis loop for hard bugs and performance regressions. Use when the user says "diagnose"/"debug this", or reports something broken/throwing/failing/slow.

discovery-research-engine

Investigate an open research question through competing explanations, diverse relevant evidence and tests that could disprove the leading answer.

domain-work-factory

Plan and verify non-code deliverables such as reports, contracts, spreadsheets, campaigns and media using the appropriate domain skills and tools.

grill-me

Thoroughly stress-test a plan, idea or consequential choice when the user wants questioning. Explore dependencies and important assumptions, explain alternatives fairly and keep asking beyond sixteen questions when useful.

how

Explain a codebase, system or process from its real sources, at the depth the user needs.

interrogate

Independently challenge a plan, change or claimed result and find concrete risks, scope mistakes and unsupported assumptions.

jev-build

Build, review or debug Jev integrations using the official SDK and relevant existing recipes. Covers all typed questions, experimental images, batched judgments, uncertainty and measured deployment.

jev-context

Use Jev selectively to choose relevant context, inspect competing memories or advise on native compaction. Useful for a large or conflicting context set; ordinary replies and routine record capture need no Jev call.

jev-quality

Use Jev to prioritise real tests, triage failures, assess evidence with explicit rubrics, or evaluate a Jev workflow's accuracy, latency and cost. Complements actual tests and outcome verification.

jev-research

Use Jev selectively to rank supplied evidence, search large document sets, check claim support or select exact values. Use when Jev-assisted research is requested or a measured retrieval workflow needs these judgments.

jev-risk

Use Jev as a bounded second look at scope drift, consequential unanswered questions or risky proposed changes. Complements BGZFLOW's questioning and risk methods without granting permissions or blocking routine replies.

jev-workflows

Compose several Jev capabilities with reasoning, retrieval and observed tool feedback for an authorised goal. Use for dynamic questions, hierarchical choices, composite scoring or decision loops that one judgment cannot resolve.

land-it

Integrate a finished code change using the project’s existing version-control and release workflow after relevant checks pass.

maintain-verification-skill

Keep a project's verification skill and feature map aligned with current user journeys and actual behaviour after changes, or audit the whole map when requested.

mutation-testing

Configures mewt or muton campaigns, analyzes surviving mutants, and investigates bugs exposed by testing gaps. Use when setting up mutation testing, reviewing campaign results, identifying equivalent mutants, or finding bugs from surviving mutations.

openui-generative-surfaces

Choose and implement a useful interactive surface for structured AI results or a product interface, using existing components and the actual user brief.

principle-exhaust-the-design-space

Compare plausible design or architecture alternatives when an important choice is unresolved, using prototypes only where they resolve real uncertainty.

principle-prove-it-works

Apply after completing a task, before declaring done. Verify against the real artifact (run the feature, read the actual value, inspect the diff), not a proxy, self-report, or 'it compiles.'

property-based-testing

Writes, reviews, and debugs property-based tests — Hypothesis, fast-check, proptest, jqwik, rapid, and Echidna or Medusa for Solidity invariants. Use whenever tests should cover a whole input domain instead of a hand-picked list of examples: encode/decode and serialize/deserialize pairs, parsers, canonicalizers and normalizers, validators, numeric and Decimal types, comparators and sort order, data structures, and smart-contract state invariants. Also use when adding cases to an existing @given, fast-check, or proptest suite, when judging whether existing property tests assert anything real, and when a generator has shrunk a counterexample and you need to tell a wrong property from a genuine bug. Not for coverage-guided binary fuzzing (libFuzzer, AFL), mutation-testing campaigns, static analysis, benchmarking, or end-to-end UI tests.

research-owl-jobs-to-be-done

research-owl-journey-map

research-owl-metrics-definition

research-owl-opportunity-framework

research-owl-parallel-concepts

research-owl-prototype-strategy

research-owl-qual-quant-triangulation

research-owl-research-repository

research-owl-service-blueprint

research-owl-summarize-interview

research-owl-survey-design

Design unbiased survey instruments — question wording, scales, and sampling — to measure attitudes at scale. Use when you need quantitative breadth.

research-owl-test-scenario

Write realistic usability task scenarios with success criteria and facilitation notes. Use when you have a study and need the tasks.

research-owl-usability-test-plan

research-owl-user-persona

research-scout-ground-truth

Investigate material unknowns, current interfaces and reusable tools before a consequential choice, using authoritative sources and the actual project state.

risky-changes

Check assumptions and actual impact before changing APIs, provider data, billing, pricing, quotas, defaults, permissions or other behaviour where a mistake could harm users. Use when passing tests may hide a real-world regression.

risky-decisions

Examine the consequences of a change to shared behaviour, sensitive data, external actions or important professional conclusions before committing to it.

sharp-edges

Identifies error-prone APIs, dangerous configurations, and footgun designs that enable security mistakes. Use when reviewing API designs, configuration schemas, cryptographic library ergonomics, or evaluating whether code follows 'secure by default' and 'pit of success' principles. Triggers: footgun, misuse-resistant, secure defaults, API usability, dangerous configuration.

sitrep

statechart

Draw how any system moves between states, such as a product flow, a protocol, or a service, as a Mermaid statechart from a TLA+ model. Each bug is a numbered path with blue borders to a state that breaks a rule. Use for /statechart, to show a bug as a path through states, or to turn an agreed chart into a TLA+ skeleton.

tdd

Build a requested behaviour or repair a bug through a failing behavioural test followed by the implementation, using the real public interface and the project's existing test tools.

teach-me

Explain or teach a subject at the learner’s level, using concrete examples, useful practice and optional visuals when requested.

tune-repo

Improve a repository’s development feedback and navigation when setup or tooling improvements are requested.

use-my-browser

Perform an authorised browser task through the available browser controls, verifying the intended page and the result of each consequential action.

verified-truth-research

Check important factual claims against applicable primary evidence, keeping observation, supported interpretation and uncertainty distinct.

verify-this

Verify a claim with fresh local evidence: restate it falsifiably, capture baseline and treatment, compare artifacts, and return VERIFIED, NOT VERIFIED, or INCONCLUSIVE.

workflow-scan

Find worthwhile recurring work to automate from the user-authorised history or examples, without starting automations or exporting private conversations.

write-a-prd

Write a useful product brief from the user’s goals, clarifying consequential gaps and defining observable success without inventing features.
