## 2.3.2 — fast confirmations and stronger outcome evaluations

Plain confirmations such as “Yes, that's right” no longer scan history or select
methods again. Preserve the original answer, pending compaction recovery,
explicit method requests and known stage changes. Mixed instructions and action
choices still take the ordinary path; the shortcut grants no tool authority.

Add native acceptance cases that require generated tests to catch a real rounding
bug and another wrong implementation, then check fresh inputs and the actual
command-line integration. Add a case that consumes a tested private method on a
later task while keeping it out of another project's catalogue. These evaluation
tools are development dependencies, not additional plugin startup work. The
private-method case supplies its candidate and checks; it does not demonstrate
autonomous discovery or unrestricted self-improvement.

## 2.3.1 — preserve a project's conversation across folder changes

remain boundaries; unrelated projects are not merged. Existing original records
are retained during any separately authorised recovery.

## 2.3.0 — Jev beyond model and skill selection

Expand `bg-jev` into a general entry point and add six selective specialists:
`jev-research`, `jev-quality`, `jev-context`, `jev-risk`, `jev-workflows` and

## 2.2.3 — avoid empty final routing calls

After successful ranking, skip the final model call when no additional skill or
model choice remains. Preserve explicit methods, dependency checks, cancellation,
main-agent fallback and reselection when the task or available capabilities change.
Retain only small numeric phase diagnostics in existing route records; reused
routes do not repeat old call costs. Elapsed routing time excludes prior catalogue
discovery; per-phase call time is cumulative, so concurrent calls can overlap.

## 2.0.0 — adaptive foundation

Replaces the compulsory paperwork workflow with selective method delivery,
session continuity and narrow observable checks. Jev selection uses the official
SDK and a large catalogue, with explicit main-agent fallback when unavailable.
Provider choice uses supplied real capabilities and shared resource pools.

The current source and built package expose the foundation commands. Local mail
keeps its existing implementation and storage; `bgz mail` forwards to it. Historical
commands are retired; private historical records are excluded from this public source tree.

Retired from active entry points: automatic skill forging, mandatory clarity and
readiness scores, fixed councils, receipt-based completion and reply-blocking stop
loops. Existing project evidence remains historical evidence, not a release grant.

Validation covers catalogue and routing boundaries, continuity, and selected live
method scenarios. Selection quality still needs broader evaluation; overlap and
missing expertise remain possible. Native host delivery and real task effects must
be verified independently. No claim of perfect routing or zero hallucinations.

Earlier private changelogs describe the previous design and are excluded from this public tree.
Its historical enforcement claims are not promises made by this release.
