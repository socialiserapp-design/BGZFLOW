# The short verbs

Each of these hands off to one owner node. Open it, follow it, and stop where the owner says to stop.

## /design-engineering diagram [what]

Decide whether to draw at all, and on which surface ([diagram-decision](../diagram/diagram-decision.md)). A finished figure follows [diagram-craft](../diagram/diagram-craft.md) (diagram-design when installed, [diagram-design-reconciliation](../diagram/diagram-design-reconciliation.md)). A live, editable canvas or a `.tldraw` file follows [tldraw-canvas](../diagram/tldraw-canvas.md).

## /design-engineering options [what]

Aliases: `variants`, `explore`. The user is undecided. Build the genuinely different directions needed for the current decision behind a live picker, record the decision, then preserve the harness unless cleanup is authorized ([prototype-picker](../meta/prototype-picker.md)). "Something like…" with no spec → [vibe-to-generator](../meta/vibe-to-generator.md).

Sub-modes of `options`:
- `riff`: further meaningful directions near the one you kept.
- `tune`: add a control panel to the kept direction and nothing else.
- `mix`: take parts of other variants onto the chosen base, as a matrix of portable features ([prototype-picker](../meta/prototype-picker.md)).
- `keep`: record the decision and preserve the harness unless cleanup is authorized. Keep the worst-case data as a fixture.

## /design-engineering pick "a task"

Aliases: `library`. Name the task, not the library the user named. Read `package.json` first: compare the existing solution with alternatives by fit, correctness and maintenance; do not replace a working dependency without a concrete need and authority. Recommend one maintained library, with its install line and the reason, and say so when the best fit is off your trusted list. If a few lines of code would do, say that instead ([dependency-discipline](../philosophy/dependency-discipline.md)).

## /design-engineering name "the thing"

Aliases: `word`, `vocab`. **Posture: name.** Give the precise term from [design-vocabulary](../meta/design-vocabulary.md) and the node that goes deeper, in one line, then stop. Write no code.

## /design-engineering which [job]

Aliases: `route`, `who`. Say which node, subagent or installed companion owns the job, and why, concisely ([skill-router](../meta/skill-router.md)). If the request is only for routing, answer that question. If it authorises the work too, continue within scope instead of stopping solely because this reference is a routing menu.

## /design-engineering agentation

The Session-2 fix loop ([agentation-workflow](../meta/agentation-workflow.md)). Pull annotations from the Agentation MCP server, or from markdown the user pastes. Fix one annotation at a time with minimal diffs that you can defend in [review-format](../meta/review-format.md) terms, and commit only if asked. With no annotations, ask the user to export or paste them. You may delegate to `agentation-fix-loop` where the host has it.

Personal taste and lessons belong in existing private project records. Do not create or edit an installed POV/gotchas file or spawn a curator as a side effect.
