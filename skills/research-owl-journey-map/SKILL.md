# Journey Map

Use this method only for the current research question. Reuse the existing brief, applicable user answers and private records; several selected methods contribute to one investigation, not repeated interviews. Inspect permitted actual evidence and preserve source links. Do not invent participants, quotations, emotions, findings, measurements or approvals; mark hypotheses and missing data explicitly. Planning a study does not authorise recruitment, messages, recording, tracking installation, spending, account changes or product changes. The current task and host permissions govern; shared automatic records are not proof that a study ran.

Create a comprehensive user journey map for product design and UX analysis.

## Context


## Domain Context

- Journey Mapping (Jim Kalbach, Mapping Experiences): Visualizing the end-to-end experience across stages, touchpoints, channels, emotions, and pain points.
- Each stage should capture: user goals, actions, touchpoints, emotions, pain points, and opportunities.
- Journey maps should be persona-specific when possible.
- Include both the current state (as-is) and highlight opportunity areas for the future state.

## Instructions

The user will describe the product/feature and target user. Work through these steps:

1. **Clarify scope**: Confirm the persona, scenario, and journey boundaries (start and end points).
2. **Define stages**: Identify stages within the agreed scenario; do not impose a funnel, advocacy phase or count.
3. **Map each stage** with:
     - User goals for this stage
     - Actions and behaviors
     - Touchpoints and channels
     - Thoughts and questions
     - Reported emotion with source support, or a labelled hypothesis; do not invent an emotional score
     - Pain points and friction
     - Opportunity areas for design improvement
4. **Visualize the emotional curve**: Show an emotional curve only where evidence supports it; retain missing observations.
5. **Prioritize opportunities**: Compare relevant opportunities by impact, feasibility and evidence without a fixed list length; a recommendation does not add scope.
6. **Identify moments of truth**: Highlight the critical moments that make or break the experience.
7. Explain the relevant rationale and evidence. Present in a clear, structured format.
