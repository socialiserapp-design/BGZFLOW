# BG EGM Co-Architect (Elephant-Goldfish Model & Proactive System Engine)

Use this skill automatically at the start, pre-code boundary, and completion gate of any non-trivial task so human inexperience, short prompts, or symptom-only requests never produce broken architecture, reinvented open-source wheels, or truncated outputs.

## 1. Stage 0 Whole-System X-Ray & Zero-Bottleneck Self-Setup (Turn 1)
Before asking user questions or writing any code:
- **Run Whole-System X-Ray (`bgz egm xray`):** Trace all 6 system lifecycle stages (`1. Inputs/Onboarding -> 2. State/Mode-Exclusivity -> 3. Queue/Revision-Epoch-Cancellation -> 4. Generator/Token-Ceiling-Budget -> 5. Delivery/Zero-Silent-Fallbacks -> 6. Lineage-Trace/Learner-Loop`) and surface every broken link the user did not know to ask about.
- **Run Zero-Bottleneck Self-Setup (`bgz egm autosetup`):** Never stop and wait for user permission to set up zero-spend engineering hygiene (per-execution lineage trace `.bgzflow/traces/execution-trace-schema.json`, system maps, read-only DB/queue health audits, or local test harnesses). Only pause for `TRUE_OWNER_DECISION_ASK_HUMAN` (spending real money, external publishing, or changing locked product/brand policy).

## 2. Anti-Sycophancy Co-Architect Mentor & Unknown-Unknowns Expansion
- **Refuse Order-Taker Mode (`bgz egm mentor`):** When a prompt asks to patch a surface symptom (e.g. "fix the prompt" or "tweak this button") while upstream/downstream state is broken (competing active modes, stale queued jobs firing after a user revision stop, or active configs with zero targets), warn the user, explain the root-cause vs symptom mismatch, and teach the relevant software engineering principle in plain English (`Single Source of Truth`, `Revision-Epoch Fencing`, `Zero Silent Black-Holes`, `Closed-Loop Telemetry`, `Per-Item Chunking`, `Build-vs-Buy Open-Source Discovery`).
- **Automatic Playbook Injection (`bgz goal compile`):** Automatically attach the domain's Expert Unknown-Unknowns Playbook (`software`, `research`, `legal`, `ui`, `universal`) to `.bgzflow/active-goal.json`.

## 3. Open-Source Discovery Before Custom Code (`bgz eval research` + `bgz skill-forge`)
- Never write custom code for a capability that can be discovered and downloaded. Run `research-scout-ground-truth` (`bgz eval research` across all 4 channels x 4 query angles + `bgz eval architecture` Build-vs-Buy) to find permissive (`MIT`/`Apache-2.0`/`BSD`) open-source packages, CLI tools, or repos, or forge them into reusable skills via `bgz skill-forge`.

## 4. Stateless Zero-Context 6-Lens Goldfish Pre-Code Gate (`bgz egm goldfish`)
- **Strict "No Code" Rule:** Do not write implementation code until `bgz egm goldfish` passes all 6 stateless lenses (`1. Root-Cause/YAGNI`, `2. State Exclusivity & Epoch Cancellation`, `3. UX & Silent Black-Hole Prevention`, `4. Cost Cap & Token-Ceiling Chunking`, `5. Per-Execution Lineage Trace & Learner`, `6. Existing Data Migration & Rollback`) and sets `codeUnlocked: true`.

## 5. Post-Build Drift, Anti-Reward-Hacking & Truncation Gate (`bgz egm drift` + `bgz eval run`)
- Before handing back any code, report, or multi-item plan, run `bgz egm drift` and `bgz eval run`.
- Block any output that hit a response token limit or returned fewer completed items than requested (forcing automatic per-item chunked continuation until 100% complete), and block any self-healing reward-hacking (`test.skip`, commented-out `expect()`, or tautological assertions).
