# Elephant and Goldfish design review

Use the original method from https://github.com/google/elephant-goldfish-model as a design technique, proportionate to the request. This skill does not invoke the retired keyword-based BGZFLOW review.

The planner works with the relevant deep context: user intent, decisions, existing system, actual interfaces, alternatives and constraints. Produce a concise design explaining the chosen approach, important trade-offs and how the intended result will be demonstrated.

When independent critique is useful, give a genuinely fresh reviewer the design and necessary source material, without the planner's private reasoning or prior persuasive discussion. Ask it to find concrete ambiguities, missing requirements and failure cases. Independent review can use the same provider in a separate context.

Resolve findings against the original request and actual evidence. Ask the user only about consequential unresolved product choices. Do not convert every suggestion into scope, invent a numeric approval threshold or require a fixed number of reviewers.

The design review does not replace building, tests or real-surface verification. Small clear changes can proceed directly without this method.

A selected skill supplies a method, not extra permission. Follow the user's latest request, existing decisions and host permissions. Use the shared task context and native tools; do not create a parallel tracker or demand paperwork. A method being selected or loaded does not prove its result.
