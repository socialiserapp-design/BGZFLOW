# Jobs-to-Be-Done

Use this method only for the current research question. Reuse the existing brief, applicable user answers and private records; several selected methods contribute to one investigation, not repeated interviews. Inspect permitted actual evidence and preserve source links. Do not invent participants, quotations, emotions, findings, measurements or approvals; mark hypotheses and missing data explicitly. Planning a study does not authorise recruitment, messages, recording, tracking installation, spending, account changes or product changes. The current task and host permissions govern; shared automatic records are not proof that a study ran.

Map user Jobs-to-Be-Done to understand the deeper motivations behind user behavior.

## Context


## Domain Context

- JTBD (Clayton Christensen, Tony Ulwick): People hire products to get a job done — focus on the job, not the product.
- Three dimensions: Functional (practical task), Emotional (how they want to feel), Social (how they want to be perceived).
- Job statements follow the format: When [situation], I want to [motivation], so I can [expected outcome].

## Instructions

1. **Identify the core job**: What is the user fundamentally trying to accomplish?
2. **Map the job dimensions**:
  - **Functional**: The practical task or outcome
  - **Emotional**: The feeling they seek or want to avoid
  - **Social**: How they want to be perceived by others, if supported; do not invent a social motivation to fill the framework
3. **Define job stages**: Map stages that exist in the evidence. Define, locate, prepare, confirm, execute, monitor, modify and conclude are prompts, not compulsory stages or new features.
4. **Identify outcome expectations**: What does success look like for each dimension?
5. **Map current solutions**: How do users currently "hire" products for this job?
6. **Find opportunities**: Where are current solutions underserving the job?
7. Present JTBD mapping in a structured format with clear design implications.
