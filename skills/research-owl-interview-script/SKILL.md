# Interview Script

Use this method only for the current research question. Reuse the existing brief, applicable user answers and private records; several selected methods contribute to one investigation, not repeated interviews. Inspect permitted actual evidence and preserve source links. Do not invent participants, quotations, emotions, findings, measurements or approvals; mark hypotheses and missing data explicitly. Planning a study does not authorise recruitment, messages, recording, tracking installation, spending, account changes or product changes. The current task and host permissions govern; shared automatic records are not proof that a study ran.

Create a structured user interview script for qualitative research.

## Context


## Domain Context

- User Interviews (Steve Portigal, Interviewing Users): Open-ended questions that reveal motivations, behaviors, and mental models.
- Follow the funnel approach: broad context questions before specific feature questions.
- Use JTBD probing: When did you last...? What were you trying to accomplish? What happened next?
- Avoid leading questions and treating hypothetical intentions as observed behaviour. A closed screening or confirmation question can be appropriate; use a neutral open probe where useful.

## Instructions

1. **Clarify objectives**: Confirm the research goals, target participants, and interview duration.
2. **Create the script** with these sections:
   - **Introduction** (fit the available session): Welcome, explain purpose, set expectations, get consent
   - **Warm-up** (only relevant background): Easy context-setting questions about their background and role
   - **Core exploration** (proportionate to the study question): Deep-dive questions organized by research theme, with follow-up probes
   - **Specific scenarios** (where they answer the study question): Walk-through of specific tasks or experiences
   - **Wrap-up** (allow corrections and omissions): Summary, anything we missed, next steps, thank you
3. **Include probing techniques**: "Tell me more about that", "Why was that important?", "What happened next?"
4. **Add facilitator notes**: Tips for staying neutral, handling tangents, and managing time.
5. Explain the relevant rationale and evidence. Present the script in a ready-to-use format.

## Question Quality Guardrails

**Ensure all questions are non-leading.** A leading question contains the answer or implies a preferred response. Replace any question that assumes sentiment, behaviour, or outcome.

| Leading (avoid) | Non-leading (use) |
|---|---|
| "Was that frustrating?" | "How did you feel about that?" |
| "Did you find it easy?" | "How easy or difficult was that for you?" |
| "Did you like the feature?" | "What did you notice about that feature, if anything?" |
| "Would you use this?" | "How would you use this in your work, if at all?" |

**Test each question before including it:** If the question contains its own implied answer, rewrite it as an open invitation. Use an open follow-up where it adds needed understanding; do not mechanically extend every closed question or repeat an applicable prior answer.
