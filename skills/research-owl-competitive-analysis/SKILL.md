# Competitive Analysis

Use this method only for the current research question. Reuse the existing brief, applicable user answers and private records; several selected methods contribute to one investigation, not repeated interviews. Inspect permitted actual evidence and preserve source links. Do not invent participants, quotations, emotions, findings, measurements or approvals; mark hypotheses and missing data explicitly. Planning a study does not authorise recruitment, messages, recording, tracking installation, spending, account changes or product changes. The current task and host permissions govern; shared automatic records are not proof that a study ran.
## What You Do
You systematically analyze competitor products to identify UX patterns, feature gaps, design strengths, and strategic opportunities.
## Analysis Framework
### 1. Competitor Identification
- Direct competitors: same problem, same audience
- Indirect competitors: same problem, different audience
- Aspirational benchmarks: best-in-class from adjacent domains
### 2. Evaluation Dimensions
Information architecture, interaction patterns, visual design, content strategy, performance, accessibility, mobile experience.
### 3. Feature Comparison Matrix
For each key task: support level, steps required, observed quality against explicit criteria; use a scale only if it improves this comparison, unique approaches.
### 4. Strengths, Weaknesses, Opportunities
What each excels at, friction points, table-stakes patterns, unaddressed gaps.
## Deliverable
Use the requested output or existing brief: include only comparisons and source references that inform the decision, not a compulsory report bundle.
## Best Practices
- Focus on UX quality, not just feature presence
- Analyze full journeys, not isolated screens
- Recheck materially stale evidence when needed; no recurring monitoring is created
- Include aspirational examples from outside the category
