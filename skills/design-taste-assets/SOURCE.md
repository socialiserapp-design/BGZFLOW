# Source and adaptation

Imported from [Leonxlnx/taste-skill](https://github.com/Leonxlnx/taste-skill), pinned
to the revision recorded in `source-manifest.json`. Every one of the 1,617 source
skill files was downloaded and verified against the repository tree's Git blob
identity before import. The complete original remains in the private research
capture. All source file bytes are retained here, with deliberate path treatment:

- Browser assets and palette/type data retain their original relative paths.
- The upstream SKILL and detailed references are `.source.txt` inspection material,
  not a nested skill or authority over current design decisions.
- Top-level scripts and ten asset-side `.mjs` build/browser tools are retained as
  non-executable source text. Their process, network, output cleanup and automatic
  style/history operations are not browser runtime dependencies. They are not
  silently enabled by importing the library.
- `scripts/library.mjs` is a new narrow offline adapter over the existing asset
  metadata. It searches without upstream trade/style bans, verifies retained bytes,
  and exports a fresh complete browser asset tree plus attribution. It is not a
  rewritten browser automation or asset-generation framework.

Each original file's source path, retained path, byte count, integrity value and
treatment are on disk in the manifest. No asset was excluded to meet a count
quota. Remote-only photo records remain metadata; no extra photographs, fonts,
packages or accounts were acquired. Demo content and defaults remain examples.

Static import/bundle checks cover shared JavaScript dependencies; dynamic family
modules, CSS, images and metadata stay together in the full export. These checks
do not establish rendered visual quality or correct GPU/browser behaviour.
