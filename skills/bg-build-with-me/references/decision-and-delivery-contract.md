# One current brief connecting intent and evidence

Use the project's existing records and [shared language](glossary.md). Maintain
a concise current view of what the user wants, why the chosen work meets it,
what is authorized and what would demonstrate success. This is not a mandatory
JSON schema, separate tracker or permission gate.

## Product plan

For substantial work preserve:

- The original outcome, intended users or environment and latest corrections.
- Observable success, consequential failure cases and unresolved questions.
- Current user decisions, standing permissions and active holds, kept separate
  from agent recommendations and historical decisions.
- The smallest complete approach, relevant alternatives, dependencies and ownership.
- Selected expertise and meaningful checks for the actual risks.

Clarify a material missing choice before dependent work; continue independent
authorized work. Update the brief when facts or instructions change, not after
every command. No fixed length, readiness score or model council is required.

## Worker assignment and body delivery

Use a capable single agent or independent workers according to the work and
observed resources. Follow [supported worker routes](worker-route.md).

Give an executor the objective, inputs, owned resources, relevant instructions,
limits, expected output and checks. Deliver selected method bodies before dependent
work and restore them if lost. Selection, delivery and observed application are
different facts. A worker brief never overrides higher-priority user instructions,
host permissions, spending authority or active holds.

Keep native task identities and original outcomes so work can be correlated and
recovered. Do not duplicate secret values, whole unrelated transcripts or sensitive
data. No fixed provider, two-minute cutoff or compulsory per-stage worker applies.

## Integrated handback and review

Identify the actual candidate, completed work, meaningful observed results,
remaining findings and next action. Check combined behavior where contributions
interact. Verify the intended environment and effects; an artifact's existence,
a passing unit test or worker self-report does not prove the whole outcome.

Use an independent checker when the task or consequence requires it. The checker
must not have authored the work it claims to independently assess. It can use
the same provider through a fresh appropriate role. Preserve concrete failures
through repairs and avoid unneeded repeat reviews.

Acceptance, release authority and verified live behavior are separate facts.
Proceed with already authorized steps when the applicable checks pass; ask only
when a material unresolved choice or authority gap actually requires the user.

## Copyable templates

These are optional prompts for a short existing record, not required forms.
Omit inapplicable fields and reuse facts already available.

### Plan

Outcome and observable success; current user choices and authority; relevant
facts or uncertainty; approach, owners and dependencies; checks and next action.

### Task

Objective and inputs; owned work and limits; selected methods and available
tools; required output; behavior that demonstrates success; unresolved questions.

### Worker prompt

State the exact contribution and current decisions. Name ownership, permissions,
dependencies, relevant evidence, selected instructions and the return route.
Make required tests and unavailable surfaces clear without inventing capabilities.

### Executor read receipt

No separate read receipt is required. Use native delivery and tool observations
where available. A delivered body, a file read and appropriate application are
distinct; missing context should be restored, not certified by a model-written form.

### Handback

State what changed, what was actually checked, the result, any missing evidence
or uncertain external effect, and who owns the next action. Preserve original
test output or source references without pasting unnecessary logs to the user.

## Continuity and peer leads

Use native compaction and restore relevant current context. Preserve original
messages and evidence behind summaries; do not turn agent summaries into new
user authority. Native event capture helps but can omit unsupported operations.

For a needed handoff, retain the objective, latest corrections, owners, pending
effects, active holds, candidate, selected methods and next action. Do not force
a new chat based on transcript size. Reconcile native execution before resuming
or retrying an operation with an unknown outcome.

Use existing supported messaging only within authorization. Respect explicit
requirements for visibility and exact recipients. A sent message is not proof
of receipt or action, and an agent message is not a new user instruction.
