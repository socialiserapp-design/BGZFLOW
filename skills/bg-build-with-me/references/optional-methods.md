# Optional methods under BG trigger ownership

Useful methods from public skill collections fit inside BG routing, and a whole skill can be adopted when it fits. Keep one entry router ([BG Build With Me](../SKILL.md)), one [glossary](glossary.md), one [shared contract](decision-and-delivery-contract.md) and one [worker route](worker-route.md). Each method below is described as a capability, so the pack works without any extra skill installed. The skill names are optional suggestions from the public Superpowers collection (MIT licence). This map changes no live hook and is not a recommendation to disable that collection.

## Whole skill versus extracted method

"Whole" means read and apply the full body under higher-priority user and host instructions. "Extracted" means use the named method under BG's contract and explicitly discard the conflicting workflow. Never vendor third-party bodies or treat same-name copies as identical. Read the exact selected body with the [body read and fallback procedure](skill-selection.md#body-read-and-fallback-procedure). A method review does not certify a skill's helper scripts or prove its tool ran.

| Method | Optional skill (if installed) | Adoption | Useful action and output | Trigger owner and adaptation |
|---|---|---|---|---|
| Verification before completion | `verification-before-completion` | Whole method | Identify the decisive command, run it, inspect the complete result and bind claims to actual evidence | Verification owns the handover check. Reuse valid unchanged evidence and label native and unrun checks. A self-check never becomes independent acceptance |
| Systematic debugging | `systematic-debugging` | Extract the four phases | Reproduce, trace the cause, compare working patterns, test one hypothesis, then fix and verify | BG's debugging trigger. The two-repair-round cap replaces the source's own escalation threshold. Preserve unclear environmental evidence |
| Test-driven development | `test-driven-development` | Extract red, green, refactor | Show the test failing for the intended defect, make the smallest correct fix, run the relevant regression check | Changed behaviour owns the trigger. Keep existing authorised work; never delete someone else's code or impose tests on prose to satisfy ceremony |
| Brainstorming | `brainstorming` | Extract context, alternatives and design isolation | Inspect the existing flow, expose material product choices and produce a represented design | BG discovery owns questions and approval boundaries: use the [question round](../../bg-plain-english-builder/references/question-round.md#copyable-question-round) and the [prototype interface](../../bg-plain-english-builder/references/planning-loop.md#prototype-interface). The founder's recorded decisions (the project's `DECISIONS.md` or the overlay `FOUNDER.md`) stay settled. No blanket approval before every small action |
| Writing plans | `writing-plans` | Extract file, interface and acceptance detail | Name what each task consumes and produces, its dependencies, exact owned files and meaningful checks in the existing plan | BG planning owns the plan. Replace forced fresh-agent-per-task, two-stage reviews and execution menus with the accepted route. Keep global constraints in every packet |
| Parallel agents and worktrees | `dispatching-parallel-agents`, `using-git-worktrees` | Extract isolation, ownership and complete packets | Reuse owned worktrees, dispatch independent ready tasks, check overlap and integrate exact candidates | Delivery owns launch and merge under the [worker route](worker-route.md). Spawn workers only within the brief's authority. Reject unsafe shared-directory fallbacks and unsupported concurrency claims |
| Executing plans | `executing-plans` | Extract plan reconciliation and execution | Read the accepted plan, track each artifact and check, and report the completed contribution | The existing worker executes. No automatic alternate framework, new tracker or subagent promotion. Hold only the affected dependencies |
| Code review | `requesting-code-review`, `receiving-code-review` | Extract exact-candidate review and technical response | Give the checker requirements, base and candidate; verify findings against reality; return concrete bounded repairs | Verification owns assessment; the lead decides from a fresh read-only checker result. Consolidate findings instead of reviewing every routine task; an ambiguous item holds only the dependent repair |
| Finishing a branch | `finishing-a-development-branch` | Extract candidate, base and test reconciliation | Verify the branch, test identity and integration evidence; preserve unreviewed work | The integration writer controls merge and release under current authority and holds. No unsolicited push, menu or clean-up, and no ownership inferred from a folder name |
| Proactive skill lookup | `using-superpowers` | Extract the lookup habit | Check relevant procedures before the affected work | BG owns admission and current/next routing. Replace any "every response" or "tiny chance" trigger and compulsory brainstorming chain with the coverage floor, bounded selection and retained reads |

## Living alongside another methods framework

When a host also loads a methods framework at session start, keep one router:
1. Inventory the framework's version and its start, clear and compact injections alongside the host's own entry files. Back up the exact before-state and keep the existing supported wake and compaction controls.
2. Use one startup entry that loads BG's compact router and baseline and restores missing or changed context. Route method selection through the table above. Remove competing "always start a second workflow" instructions from that entry while keeping the useful methods available. Use only a supported, owner-controlled hook or entry mechanism; never edit a plugin cache or add a loader.
3. Bind each trigger once: discovery owns new product choices, capability coverage owns stage and platform floors, delivery owns dispatch, and verification owns independent inspection. The founder's original scope and recorded decisions outrank imported defaults.
4. Retire duplicate or unsafe startup skills only after reconciling actual discovery paths, with a backup, preserving unique source and history.
5. Qualify fresh, cleared, compacted and resumed lead and worker sessions: actual body loading, one router, no duplicate interview, board or review chain, retained holds and a native compaction fallback. Record live versus staged status, and roll back a startup change that makes behaviour worse.

## Final UI polish and new looks

Run a final polish pass on every UI screen as the last design step (see [final polish](../../bg-personal-product-design/references/techniques.md#final-polish)). An installed polish skill, for example `gpt-taste`, can serve as that pass; whether a specific skill is required is set by the founder's recorded decisions. When you use one, run it in full, treat its fixed fonts and layouts as one style option, and keep an approved look's fonts, layouts and tokens. Run any randomisation or code it asks for for real and record the result; never simulate output or hide overflow to conceal a defect.

A new look starts with [at least eight genuinely different directions](../../bg-personal-product-design/references/techniques.md#eight-or-more-rendered-directions). There is no universal dark or glass default. An approved look changes only by the founder's decision. Keep rich effects on capable devices and reduce only the affected effects on constrained devices. The coverage floor never invents style presets.
