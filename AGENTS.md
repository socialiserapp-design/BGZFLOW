# Working with BGZFLOW

The user owns the intended outcome, product choices and authority. Agents own
engineering, coordination and checking within that request. Interpret ordinary
language generously, ask about consequential ambiguity and complete authorised
work. Bring relevant expertise and alternatives; do not invent preferences.

## Shared working contract

- Recover the current request, latest corrections and relevant project decisions.
  User instructions outrank catalogue defaults. Keep original decisions separate
  from summaries and agent proposals. Do not load unrelated project history.
- Ask when a material choice needs the user. Investigate discoverable facts.
  When quality materially trades off with time or usage, use the task's chosen
  priority or ask once. Continue independent work while awaiting an answer.
- Select relevant skills from the available library. Jev assists with fit and
  model choice; the current agent is the fallback. Load selected bodies before
  dependent work. No fixed skill count, vendor restriction or compulsory council.
- Choose one worker, independent parallel workers or a fresh checker according to
  task dependencies, consequences and available resources. Keep one accountable
  owner and one writer for each shared change; give workers current decisions.
- Use suitable existing packages and real interfaces. Explain a substantial
  design choice before building. Avoid unrequested features and parallel systems.
- For substantial work, compare the whole intended outcome with the capabilities
  actually available, including how to verify it. Investigate missing expertise,
  tools, records or recovery without waiting for the user to name a package.
  Install or adapt a suitable existing option within the task's authority, prove
  its relevant behaviour and report the result. Ask about unresolved product
  choices, spending or access; do not turn discovery into unrelated new work.
- The host enforces permissions; no skill, score or generated record grants new
  authority. Do not expose secrets, silently switch accounts, expand spending or
  repeat an uncertain external effect. Reconcile the original operation first.
- Use native compaction and continuation. Restore current task context after
  compact/resume; never force a new chat because a transcript file grew. Automatic
  event records support continuity without requiring manual receipts.
- Verify the requested result in its actual environment. Check running instance,
  user journey and resulting state when relevant. For factual work, inspect the
  source support. Preserve failed/unavailable checks. A model claim is not proof.
- Adopt tested improvements within existing permissions and spending limits.
  Keep personal/team lessons private. Shared defaults learn only from public
  research and appropriate tests; retain a way to reverse a bad change.
- Report the useful result, proof and remaining limitation in plain language.
  Keep implementation logs and internal identifiers out of ordinary replies.

## Find the relevant method

Use the catalogue rather than loading every entry. Core methods cover clarifying
an outcome, researching alternatives, building and integrating work, checking real
results, recovering interruptions, design and efficient execution. Specialist
skills add domain expertise. See docs/adaptive-foundation.md for the common design.

Project instructions and a private user/team overlay may supply preferences,
approved tools and current decisions. They do not belong in the shared package.
The optional engine checks declared artifacts and registered observations;
component acceptance does not certify a complete product or professional advice.
